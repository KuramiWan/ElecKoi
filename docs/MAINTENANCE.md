# 文档维护约定

当前开发规范、使用教程和架构决策各有一个正式入口，避免同一规则在多份文档中独立演进。

## 目录职责

| 位置 | 用途 |
| --- | --- |
| `README.md` | 文档导航 |
| `DSH_DESKTOP_ARCHITECTURE.md`、`DATABASE.md`、`DSH_PLUGIN_MIGRATION.md` | 当前架构、数据与插件归属 |
| `plugins/` | 正式插件教程和公开合同 |
| `adr/` | 编号稳定的架构决策，包含状态与替代关系 |
| `history/` | 废弃架构说明，不指导新增实现 |
| `open-problems/`、`screenshots/` | 公开课题和正式产品截图，存在时独立维护 |

其他产品格式或设计文档按当前仓库需要保留，不因目录同步自动进入另一仓库。

## ADR 编号

- 编号是决策标识，不是教程章节；允许缺号，不补造文档，也不重排既有编号。
- 同一编号只能对应一个标题和文件名，两边共有的记录必须使用同一身份。
- 新增记录前核对两个工作树的最大编号，从尚未使用的下一号开始。未进入某个仓库的编号也不能被另一项决定复用。
- 本次编号冲突保留 `0020-roleplay-history-recovery.md`；模型配置记录使用 `0022-model-configuration-request-contract.md`，`0021` 保持不变。
- 每份记录注明状态；被取代时写明后续记录。变更编号、路径或状态时同步更新索引和所有引用。
- 旧决策保留来龙去脉，但不能与当前规范并列成为另一套开发标准。

## 两个工作树的文档同步

- 共享技术文档使用同一目录、文件名和 ADR 编号；内容更新必须对照目标仓库实际代码，不把未实现的能力写成现状。
- 同步前逐文件比较，列出新增、修改、移动和删除范围。禁止整包覆盖 `docs/`。
- 公开目录已有课题、中英文内容和正式截图独立维护，不能被开发目录缺少同名文件所删除。
- 私有知识库、内部调研、临时截图和审查产物不自动进入公开仓库。新增公开文档先核对内容及目标实现。
- 新增或移动文档后更新本仓库首页和 ADR 索引；相对链接随文件所在目录一起修正。
- 自动生成的接口总表在目标仓库按其实际 manifest 生成，不从另一工作树直接复制。

## 检查

```powershell
pnpm check:docs
pnpm check:plugin-docs
```

修改 bundle 开发接口后运行 `pnpm generate:plugin-docs`，再校验。源码构建包含以上检查。

`node scripts/check-docs.mjs --compare <另一工作树路径>` 额外核对两边共有 ADR 的编号、文件名与标题；它只读取文档，不执行同步，也不会公开另一工作树的内容。
