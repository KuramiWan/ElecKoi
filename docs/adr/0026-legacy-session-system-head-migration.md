# ADR 0026：旧 Session 系统开头的迁移修复

## 状态

已采纳，2026-10-06。补充 ADR 0020；取代其要求单个会话恢复失败阻止整个 Host 就绪的决定。

## 问题与依据

锁定 DSH `0.2.0-rc.2`、提交 `c1b47e41fcd54d20a0f061df28683bfc29ee24e5` 的 v3 到 v4 相邻迁移会保留旧消息顺序。部分旧日志在首个系统消息之前已经保存用户消息，却没有预留空系统开头，最终被正式 v4 关系校验以 `system/message requires a protected first surface head` 拒绝。原日志仍存在，但不能继续聊天。

官方系统提示词合同允许空 `content` 的系统开头；它不生成模型协议消息。依据是同版本 `session-format-v2-to-v3` 的空头生成机制和 `2026-09-02-system-prompt-as-surface-node` 决策。产品运行时不另建历史读取器或兼容模型。

## 决定

1. 仅对精确版本的 `dsh-session-format-v3-to-v4` 相邻迁移增加补丁。在迁移输入中确认首个系统消息晚于其他消息时，于日志已有的首个真实 `step/start` 之后补一个确定身份的空系统开头。不新增轮次、步骤、模型请求、回复或推理，不移动已有系统提示词及其真实步骤归属。
2. 首步之前独立保存的用户输入，仅在没有跨越已结束轮次或继承边界时归入该首步的空开头之后。保留这些输入的稳定 ID、时间、正文及消息间顺序；保留所有原始请求、回复、推理、工具与其他事件。同步重定位正式事件引用，不能让引用变成未来引用。无法证明该归属或其他结构不正确时继续拒绝，不按错误字符串跳过校验。
3. 由官方格式目录串行执行原有完整迁移链，再由官方 v4 校验、编码和 JSONL 写句柄独占发布 v4 后继。v3 文件保持原字节；只读访问不写盘。发布后运行时只读取正常 v4，不维护修复分支。已有正常 v3 不增加空头，已有 v4 不经过这段修复。
4. 单个聊天的迁移、历史恢复或投影刷新失败只记录该聊天的错误，继续其他聊天和 Host 启动。打不开的会话仍由正式读取接口报错，不伪装成空聊天。

## 删除条件与验证

补丁代码旁必须记录版本范围、触发条件、数据保留约束及本 ADR。升级 DSH 时核对同版本官方相邻迁移；当官方实现覆盖本修复的输入，且 `tests/dsh-session-system-head-migration.test.js` 的磁盘迁移、原始内容、引用、重复重开与拒绝用例全部通过时，删除该版本补丁和 `patchedDependencies` 登记，并更新锁文件。不能只因桌面版本变大就删除仍需处理用户旧文件的迁移能力。

合成旧日志覆盖首步内缺空头、首步前用户输入、真实后续系统消息、引用重定位、拒绝不安全的轮次与继承归属、原文件不变、只读不发布和写入后关闭重开。正常记录与当前 v4 校验保持原行为。
