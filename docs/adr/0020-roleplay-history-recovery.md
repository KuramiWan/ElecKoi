# ADR 0020：旧聊天历史与回退状态恢复

## 状态

已采纳，2026-10-02。

启动失败范围由 [ADR 0026](0026-legacy-session-system-head-migration.md) 修订：单个会话恢复失败不再阻止整个客户端启动。

## 问题

部分旧聊天在请求投影中保存了尚未获得回复的历史用户输入，但没有将其写为独立 Session 消息。当前界面读取官方聊天投影，因此漏掉这部分输入。旧 SQLite 消息账本已保存变量与设定快照，却没有补入后来新增的运行状态检查点文件。

## 决定

1. Host 就绪前关闭对应 Session，取得官方写入锁；以同版本格式目录读取、编码、验证日志。仅恢复能与活动账本逐条对应的未回复用户输入，使用官方 Session append 生成消息。不补造轮次、步骤、模型回复或推理。
   若旧日志在第一步内才建立正式受保护的系统开头，历史输入插在该开头之后；不移动系统提示词，不改变其步骤归属。
2. 原 Session ID、时间、现有消息、轨迹和实际请求记录保持不变；插入消息后同步调整正式序号引用。原文件备份后原子替换，失败恢复原文件，重复运行不再插入。缺少可信来源或有歧义时保留原文件并报告错误。
   历史账本对应的 Session 在 Host 就绪前通过官方 registry 从零重放，再通过官方 cache 服务写入派生检查点，避免相同 Header 下的旧水位缓存掩盖恢复结果。该步骤失败时记录对应会话错误并继续启动，不能把读取失败伪装成空聊天；见 ADR 0026。
3. 回退优先读取当前检查点；旧聊天缺少检查点时，仅使用对应活动消息账本中已保存的变量与设定快照。没有可信历史状态时继续拒绝操作，不使用当前值冒充历史值。恢复成功后写入现有检查点文件，不新增数据库表或存档体系。
4. 回退第一轮保留此前的独立历史输入；位于首步系统开头之后的历史输入连同已有配置阶段保留，并使用原步骤和轮次结束事件闭合。删除被选输入和所有旧模型执行记录，不补造模型请求。直接删除或重新生成历史输入时，从该输入截断。始终保持原聊天与 Session ID。
5. 恢复时通过官方 append 保存可忽略的 `eleckoi/history-restored` 信息标记，仅标识已恢复消息的稳定 ID，不参与模型消息、surface 或生命周期。产品统计投影仅抵扣含这些历史输入且没有模型请求的保留配置阶段；官方统计的其他计时与速度保持不变。没有标记的正常聊天不受影响。
6. 新请求准备只读取活动分支中产品持有的开场白。历史用户输入与模型回复始终由原生 Session 提供，不为查找开场白而扫描旧消息账本或恢复旧正文读取链路。
7. 重新生成在回退前读取并验证当前模型选择与当前配置，回退后通过官方 `selectModel` 重装该选择；历史回复使用的模型不决定新请求。预设、变量桥与请求准备失败时，恢复操作前日志、变量、设定与派生投影，Client 重新读取真实消息序号。恢复所需内容只在本次操作中暂存，不新增长期消息副本。

## 验证

合成旧聊天覆盖官方持久化关闭、重开、聊天投影、序号引用、重复恢复、写入锁、回退历史输入、历史状态恢复与缺失状态拒绝。带有绑定回复的旧数据库还覆盖实际请求准备，以及 Remote 回退、准备、启动重新生成；仅模型执行被替代，不模拟请求准备。SQL 结构与版本保持不变。
