# ADR 0038：聊天运行状态由产品数据库统一保存

## 状态

已实施，2026-10-14。数据库变更合并到尚未发布的 v11 → v12。

## 决定

1. 聊天正文、思考和工具轨迹继续由锁定 DSH 的 Session 日志保存。产品 Host Repository 独占变量、分支设定及它们的历史状态，不将产品状态重复写入 Session。
2. `conversation_state_snapshots` 保存正式 Session 的轮次开始和完成边界。生成前保存 `before`，成功结束时当前变量和 `after` 在同一产品数据库事务提交。工具工作文件不承担历史保存。
3. 旧产品消息能确定归属的输入、回复状态在迁移时转为消息边界记录。消息边界与轮次边界是不同身份，不能凭序号、文本或第一个候选猜测对应关系；有正式轮次边界时优先使用它。按用户决定丢弃无法唯一对应轮次的旧回复历史；变量查看保留楼层并显示“无历史状态”，正常聊天不因此失败。
4. 不对 `agent_responses` 的 Session 与轮次组合增加未经合同确认的唯一约束。一个 DSH 轮次可包含多个助手事件；每轮状态独立于助手事件的数量。保留仍承担旧消息归属的字段，删除历史正则快照和没有生产入口的旧生成实现。
5. 普通生成和聊天导入使用同一状态 Repository。导入只保存来源明确提供的历史值，缺失历史以缺失表示，不用当前值或空对象冒充。新导入正文只进入 Session，不另创建产品回复账本。
6. 原检查点文件按用户决定退出支持，不读取、不写入、不转存，也不新增启动自动删除逻辑。磁盘已有旧文件保持原状，新生成的历史只写产品数据库。
7. 聊天导出仍是一个文件，包含产品关系、当前分支设定、状态历史及官方 Session 日志；导入、分支、删除和重新生成遵循同一边界，并在失败时恢复操作前状态。

## 验收

覆盖 v11 连续升级、未发布 v12 原子整理、磁盘重开、同轮多个助手事件、缺失和歧义历史、导入导出、回退和分支；确认运行代码不再访问旧检查点文件，核对 SQLite 结构、外键和完整性。
