# 原生作者示例

这组示例使用 ElecKoi SDK。所有人物、积分、提示词和消息均为合成内容。完整教程见 [作者 SDK](../../../docs/plugins/author-sdk.md)，参数和返回值见 [接口参考](../../../docs/plugins/author-sdk-reference.md)。

## 直接体验

1. 在角色库按 ElecKoi 格式导入 [example.character.json](example.character.json)。导入不会自动启动脚本。
2. 打开该角色配置的“脚本”，启用角色脚本库和“积分规则”，保存。它的辅助文件已随角色卡导入，不用手工绑定。
3. 创建该角色的聊天。两个开场白分别绑定“从零开始”和“从十开始”的变量配置，切换时使用对应版本的初始值。原生 HTML 开场白可更新积分、填写输入框、直接发送消息和停止生成。直接发送需要你已有的可用模型配置，不包含模型凭据。
4. 在聊天操作菜单展开“脚本”，点击“积分设置”，把倍率改为 3 并保存。关闭弹窗不会停止后台规则；下一次更新积分 5 会得到 `total: 15`、`level: 1`。
5. 尝试积分 -1：原生 Zod 拒绝修改，旧变量保持不变，也不发送后续消息。改成 12 后再次更新，应得到 `total: 36`、`level: 2`。
6. 在角色配置的“前端”导入 [frontend.html](frontend.html)，明确启用后回到聊天。这个独立页面接管聊天内容区，原输入框和聊天操作仍保留；它不是整套应用界面替换。
7. 在预设管理按 ElecKoi 格式导入 [example.preset.json](example.preset.json)，选择该预设。在角色配置的“脚本”启用预设库及其中脚本，保存。聊天菜单中的“切换简洁回复”一次切换两个明确编号的条目，不按名称寻找，也不改角色设定库。
8. 全局脚本示例 [global.js](global.js) 无辅助文件：在角色配置的全局脚本库中新建原生脚本，使用这份源码，启用脚本及全局库并保存。其他角色配置中显示同一份全局脚本，聊天菜单出现“清空输入框”。

预设切换改的是共用预设原稿，对使用该预设的后续请求生效，不是当前聊天的临时副本。首次启用规则不会自动重算已有变量；更新、重置或 Agent 下一次变量工具调用时才处理候选。选择另一开场白遵循产品原有开场白切换限制，不绕过已有对话的保护。

## 文件关系

| 文件 | 用途 |
| --- | --- |
| `character.js` | 角色脚本启动函数，注册异步派生规则和设置按钮 |
| `derive.js` | 普通辅助模块，不独立注册或重复保存变量 |
| `settings.html` | 作者设置弹窗，只改所属脚本设置 |
| `frontend.html` | 可直接导入的角色前端，也作为示例卡的 HTML 开场白 |
| `preset.js` | 用脚本设置中明确的两个条目编号批量切换预设 |
| `global.js` | 共享的输入框操作按钮 |
| `example.character.json`、`example.preset.json` | 可直接导入的原生容器，由 `pnpm generate:author-docs` 按上述源码生成 |

运行时入口由产品登记在所属目录的 `scripts/` 下，因此 `character.js` 中的 `../derive.js` 与 `../settings.html` 指向同一脚本库根目录的辅助文件。外部编辑使用角色配置标题旁的“打开目录”；不要将入口移动或改名。辅助文件更新会使旧程序退出并重新加载，设置保存不会重启程序。

示例不调用 Node，不用 npm 裸包名，不把正文变量命令交给另一引擎。作者规则只修改当前候选，Host 等待成功后接受一次。运行错误显示在角色配置；按钮错误显示在聊天菜单；设置和前端错误显示在各自页面。脚本停用或切换聊天会移除旧按钮和面板，新聊天正常运行自己的可用脚本。

## EJS显示模板示例

示例卡携带默认停用的「历史积分与选项」显示库，源码见 [display-panel.ejs](display-panel.ejs)。导入后打开角色配置的 EJS显示模板，先测试消息 `<option>进入大厅\n回旅馆休息</option>` 和变量 JSON `{"score":12}`，检查两项按钮及历史积分。明确启用库后保存，完成的 AI 回复会附加面板，按钮填写草稿；模板不结算变量或修改模型请求。实际选项数量不限为十项。语法与失败边界见 [教程](../../../docs/plugins/ejs-display-templates.md)。
